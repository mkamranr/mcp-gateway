# Threat Model

Scope: the gateway (web-ui, gateway-api, worker), its datastores, and its connections to agents and upstream
MCP servers. Method: STRIDE per trust boundary.

## Assets

Upstream credentials · agent keys · tool capabilities (what agents can do in other systems) · approval
decisions · tool arguments and results (may contain personal data) · the audit trail · encryption key and pepper.

## Trust boundaries

1. Agent → gateway (`/mcp`, `/api/v1/gateway/*`): agents are **untrusted** and may be prompt-injected.
2. Browser → console API: authenticated humans whose browsers may be attacked (CSRF/XSS).
3. Gateway → upstream MCP servers: upstreams are **semi-trusted**. Their descriptions and output are untrusted.
4. Gateway → MongoDB/Redis: internal network, authenticated.
5. Tenant ↔ tenant inside one deployment.

## Threats and mitigations

| # | Threat | Mitigations | Residual risk |
|---|---|---|---|
| T1 | Stolen or leaked agent key used by an attacker | Keys hashed with a pepper and shown once. Prefix lets you identify a key. Expiry, rotation, revocation, emergency revoke-all. `last_used_at`/source recorded. Scopes. Every call audited. | A key is a bearer token: until revoked, the attacker has that agent's permissions. Use short expiries and network controls. |
| T2 | Agent tries tools it was not granted (including hidden ones) | Default deny. Discovery filtered. Every call re-authorized. A DENY is returned before any tool-state detail. | Unknown names return `TOOL_NOT_FOUND` while existing-but-denied tools return `ACCESS_DENIED`, so tool *names* can be probed. The state of a denied tool is not revealed. |
| T3 | Prompt injection makes an allowed agent misuse an allowed tool | Least-privilege policies, risk levels, approval for high/critical tools, strict argument schemas, rate limits, output marked untrusted, full audit. | The gateway cannot judge intent inside valid arguments. Use approvals for consequential actions. |
| T4 | Malicious upstream returns injected instructions or oversized output | Output size cap, optional output-schema validation, redaction, untrusted marker. Descriptions shown as untrusted text and reviewed before enabling. | Agents must treat tool output as data. |
| T5 | Upstream changes a tool's behaviour or schema after review (rug pull) | Schema fingerprints and versions. A changed schema blocks calls until acknowledged. Re-discovery shows the diff. | Behaviour changes that keep the schema identical are not detectable. |
| T6 | SSRF via server registration (metadata service, internal admin ports) | Scheme and host validation, host allowlist, connect-time DNS resolution and IP pinning, always-blocked ranges, private ranges need both opt-ins (the platform setting *and* the per-server flag, which only administrators set). Changing where a server connects requires re-entering its stored credential and client certificate, and an administrator when the server may reach private ranges. No redirects. | Allowed private ranges are reachable by design. Restrict egress at the network layer as well. |
| T7 | Command injection via stdio configuration | Executable allowlist (empty by default), no shell, forbidden env vars (loader, interpreter and package manager variables). Only platform administrators can create stdio servers or change their command, arguments, environment or working directory: a stdio server runs on the gateway host, shared by every tenant. | An allowlisted executable is trusted code. |
| T8 | Approval bypass, replay or argument substitution | Hash-bound, AD-bound encrypted arguments. Atomic state transitions. Single-claim execution. Revalidation of every precondition, including the tool's schema and the server's destination and credentials as recorded at request time. Separation of duties: the caller, the user who delegated to it, the user who issued its credential and the agent's owner and creator can't approve. Policies only narrow the approvers; policies with no common approver role leave nobody in the tenant able to approve. The preview marks anything it leaves out. Expiry. | Approvers can still approve a harmful but valid request. Masked previews and the changes flag help. |
| T9 | Cross-tenant data access | Tenant from credential only. Tenant-scoped repositories. 404 for foreign IDs. Tenant-namespaced Redis keys. Security tests. | Platform admins can search across tenants (audited). |
| T10 | CSRF / XSS against administrators | SameSite=Strict `__Host-` cookie and double-submit CSRF token. React escaping. Strict CSP with no inline script, no CDN, `frame-ancestors 'none'`. | A compromised admin workstation remains out of scope. |
| T11 | Brute force of logins or keys | Login throttling per user and address, per account from any address (break-glass accounts exempt, so they can't be locked out) and optionally per address (`LOGIN_MAX_ATTEMPTS_PER_IP_WINDOW`, once real client addresses reach the gateway); failed attempts count, a successful sign-in returns its slot. A disabled local sign-in answers like a wrong password. Password changes are throttled too. API-key lookup throttled by prefix. Argon2id. High-entropy keys. | Distributed credential stuffing needs upstream WAF or IdP controls. |
| T12 | Audit tampering or loss | Append-only repository. Execution fails closed if audit cannot be written. Hashes instead of payloads. Exports audited. SIEM forwarding (syslog over TLS or HTTPS) copies every event off the host within seconds, at least once and in order. Failures are audited and exposed as metrics. | A DB administrator can still modify Mongo, but not copies already forwarded. Events written while forwarding is down are sent on recovery, unless retention purges them first. UDP syslog can lose events silently. |
| T13 | Secret disclosure via API, logs or errors | Whitelisted serializers. `has_secret` only. Log scrubbing. Sanitized upstream errors. No stack traces. | Secrets inside upstream *tool output* are passed through unless redaction is configured. |
| T14 | Encryption key or pepper compromise | Supplied as files or env, never stored in the DB. Optionally wrapped by a key service (Vault Transit, or a KMS/HSM through a command): files, env and backups then hold only ciphertext, the key service audits every unwrap, and destroying the key-encryption key shreds every copy ([key management](key-management.md)). Rotation tools for the encryption key and for the key-encryption key. Pepper rotation is documented (it invalidates keys). | Without a key service, anyone holding both a DB dump and the key file can decrypt upstream secrets. With one, the keys are still plain in the memory of running processes: code execution in a gateway container exposes them. Revoked key-service access stops new processes, not running ones. |
| T15 | Quota or concurrency exhaustion (DoS) by an agent | Atomic quotas at several scopes, concurrency slots, per-server capacity limiter, request body limit, timeouts. Approval requests consume quota. | Infrastructure-level DoS is out of scope. |
| T16 | Redis or MongoDB unavailable | Hard quotas fail closed. Execution fails closed without audit. Readiness probe reports the dependency. Per-worker heartbeats. Several API replicas and workers, a MongoDB replica set (`w=majority`) and Redis Sentinel are supported ([high availability](high-availability.md)). Outages answer a retryable 503, never a 500. Approved calls interrupted before dispatch are retried; after dispatch, never. Primary and master failover under load is tested in CI (`failover` job). | Availability is reduced during an outage. This is deliberate. An approved call whose result couldn't be recorded is marked FAILED, not retried: check the upstream. |
| T18 | Forged or replayed SSO sign-in (token substitution, login CSRF, open redirect, account takeover by username) | PKCE S256. State is single use, stored hashed, expires in 10 min, and is bound to the browser by an HttpOnly cookie. Nonce. Signature verified against JWKS with asymmetric algorithms only (no `none`/`HS*`). Exact issuer, audience, `azp`, expiry. Users keyed on issuer + subject. Same-username local accounts are refused unless linking is explicitly enabled. `return_to` limited to same-origin paths. No redirects followed and TLS verified when calling the IdP. Each case covered by `tests/security/test_sso.py`. | A compromised IdP, or a compromised administrator of a mapped IdP group, grants access. Removal from a group takes effect at the next sign-in, not for sessions already open. |
| T19 | Unreviewed or unauthorized policy change through policy as code (a stale or swapped plan, one team's bundle overwriting another's, prune deleting hand-made policies, a CI credential misused) | Apply makes exactly the reviewed plan: it is bound to a fingerprint of the computed changes and refused if anything changed since. Same validation as the console. Wildcard grants must be acknowledged in the file. Ownership: a bundle can't touch another bundle's policies, and prune only deletes policies the bundle owns. All or nothing with rollback. Every change audited with `source: bundle`. Plan and apply are separate roles (developer vs security admin). Global bundles need a platform admin. Safe YAML loader. Hand edits of managed policies need an explicit, audited override. Covered by `tests/integration/test_policy_bundles.py`. | Whoever holds the apply account's password can change policies within its role. Protect it as a production secret, scope it to one tenant, and gate the apply job behind protected-branch review. The gateway can't tell whether a pull request was actually reviewed. |
| T20 | Approval bypass or self-approval through delegation (delegating to an accomplice, chaining, counting one person twice, a stale delegation outliving the delegator's role) | The delegate uses the delegator's *current* roles and groups. Separation of duties is checked against delegate and delegator. One person's authority counts once (enforced in the atomic update). No chaining. At most 90 days. Only admins delegate for someone else. Every decision records both people, and delegation changes are audited. Escalation and reminders are claimed once per request. Covered by `tests/integration/test_approval_delegation.py`. | An approver can still hand their authority to a colleague of their choosing for the delegation period. Review `approval.delegation.created` events in the SIEM. Approver groups reflect the last SSO sign-in. |
| T21 | Agent impersonation through client certificates (a forged `X-Client-Cert` header, a certificate from a foreign CA, a stolen certificate without its key, one certificate mapped to several agents) | The handshake at the TLS proxy proves possession of the key. The header is accepted only when the TCP peer (never a forwarded address) is in `MTLS_TRUSTED_PROXIES` (a dedicated network in Compose; empty or catch-all values refuse to start), and the bundled nginx strips it on the console listener. The gateway re-checks issuer, validity dates and client-auth usage. A subject name or certificate maps to one active credential; ambiguous matches are refused. Credentials revoke immediately. Tested end to end in CI (`mtls` job). | Anything else on the trusted proxy network could forge the header: keep that network to the proxy and the gateway. Certificate revocation lists are the proxy's job (`ssl_crl`). |
| T17 | Supply chain | Locked dependencies (`uv.lock`, `package-lock.json`), pinned images, SBOM generation, offline bundle with checksums and image-ID verification. | Pin base images by digest in your registry. Scan images. |
| T22 | Console account compromise through the directory (LDAP filter injection, an unauthenticated bind with an empty password, a spoofed directory server, a directory user named like a local administrator, a re-created directory entry inheriting an old account) | The username is escaped (RFC 4515) and placeholders are substituted, never formatted. Empty passwords are refused before any bind. LDAPS or StartTLS only, with stdlib certificate and host-name verification; clear text can't be saved in production. Referrals are not followed. Exactly one entry must match. Local accounts never authenticate against the directory, and directory accounts are keyed on `objectGUID`/`entryUUID`. Sign-in is throttled per user and IP. Tested against real OpenLDAP in CI (`ldap` job). | Anyone who can change group membership in the directory controls access here: protect the groups named in the rules as you protect the directory's own admin groups. Sessions outlive a directory change until they time out. |
| T23 | Agent impersonation with IdP tokens (a forged or re-signed token, `alg: none` or HS256 keyed with the public key, a token issued for another API or another client, an ID token used as an access token, a long-lived stolen token) | Only configured issuers. Keys from the issuer's JWKS, asymmetric algorithms only. Exact `iss`; `aud` must be the gateway's audience, never a client ID; `exp` required and the lifetime capped; tokens with `nonce` refused; optional required scopes and `at+jwt`. Issuer + client must map to exactly one active credential, which revokes immediately. Tokens are never logged. Tested against real Keycloak in CI (`agent-oauth` job). | Tokens already issued stay valid until they expire if only the IdP side is disabled: revoke the gateway credential for immediate effect, and keep token lifetimes short. Whoever administers the IdP can mint tokens for registered clients. |
| T24 | Account takeover or lockout through SCIM provisioning (a leaked SCIM token, provisioning over a local administrator, linking a provisioned account to the wrong SSO identity, a deprovisioned user keeping an open session) | One bearer token, shown once, stored as an HMAC, compared in constant time, rotatable and revocable; failed attempts throttled. SCIM sees only the accounts it created: local, break-glass, LDAP and other SSO accounts are invisible (404) and their usernames can't be claimed (409). Members must be provisioned users. Groups match rules by `externalId` only (display names only with an explicit opt-in). Deleting a user disables all of its memberships, so a recycled userName inherits nothing. Linking to an SSO identity only by the configured claim equal to `externalId`, exactly one match, never by username. Deactivation and deletion end sessions at once; memberships are re-read on every request. Token and configuration changes audited with high severity. Covered by `tests/security/test_scim.py` and the compose smoke test. | The token can grant any role the group rules map to, including platform administrator: keep it only in the IdP and the rules narrow. Whoever controls the IdP's provisioning controls provisioned accounts. |
| T25 | Privilege escalation or cover-up by tenant roles (a developer re-pointing a server to collect its credential, a tenant admin shortening audit retention, pulling in another tenant's account, delegating someone's approval authority to themselves, pre-creating a local account that SSO later links and promotes) | Destination changes are bound to credentials (T6). Shortening audit retention is platform-admin only, and every tenant settings change is audited with old and new values. Tenant admins can't attach accounts that belong to another tenant or are platform administrators, can't rename them, and end only sessions in their own tenant. Administrators can't delegate another approver's authority to themselves. SSO never links platform-admin, break-glass or LDAP accounts by username; a linked account becomes SSO-only and its platform-admin flag follows the IdP group both ways, audited. A membership an administrator disabled stays disabled through SSO, LDAP and SCIM sync. Covered by `tests/security/test_authz_hardening.py`, `test_review_hardening.py` and `test_scim_hardening.py`. | Platform administrators are fully trusted. |
| T26 | Client address spoofing (a forged `X-Forwarded-For` to dodge `source_cidrs` policies or login throttling, forge audit records, or vouch for a client certificate) | Forwarded headers are believed only from `TRUSTED_PROXIES` (the edge network in Compose, `api.trustedProxies` in Helm); uvicorn's own handling is off. nginx overwrites `X-Forwarded-For` on every proxied location. Request ids are generated by the server, so correlation can't be faked either. | Behind a further load balancer, configure nginx's real-IP support (`web.realIpFrom`), or every client shares the balancer's address. |
| T27 | Leaks and denial of service through configuration and content (secrets in a startup error, credentials re-sent to a new SIEM, SSO or LDAP destination, regular expressions in upstream schemas that backtrack, unbounded upstream responses, redaction bypassed through embedded JSON or resource text) | Configuration errors name settings, never values. SIEM, SSO and LDAP credentials are bound to their destination like upstream ones; SIEM destinations pass the same network guard as upstreams. Schema patterns with exponential backtracking disable the tool, polynomial ones run only on capped input. Upstream bodies are capped while streaming. Redaction covers embedded JSON and resource text and hides what is too deeply nested to inspect. Audit export filters are typed. | Binary content isn't inspected for redacted fields. |

## Out of scope / not yet covered

- An external penetration test. An internal review across authorization, authentication, the tool execution path, cryptography and audit, and the deployment artifacts was done in November 2026; its fixes are in T6 to T8, T11, T21 and T24 to T27.
- SAN certificate credentials are first come, first served across tenants: a security administrator in one tenant can claim a SAN that also appears in another tenant's agent certificate, which makes that certificate ambiguous (refused). Pin certificates by fingerprint where tenants don't trust each other.
- The SBOM tools in the release job are fetched at run time without a pinned version.
- SAML sign-in (OIDC, LDAP and SCIM are supported).
- mTLS between the gateway's internal services (API, worker, MongoDB, Redis). They share a private network in
  Compose; enable TLS on MongoDB and Redis for a stricter setup ([high availability](high-availability.md)).
- Encryption inside an HSM. Keys can be wrapped by a KMS or HSM ([key management](key-management.md)), but the
  gateway decrypts with the unwrapped key in its own memory. There's no built-in PKCS#11 client: an HSM is
  reached through Vault or a command.
